DEF-001 POST /pet 未做必填字段校验，缺少 name/photoUrls 仍创建成功并返回 200 high / contract

端点：POST /pet

证据：期望 400/422，实际 200，响应体 {'id': 987654322, 'photoUrls': [], 'tags': [], 'status': 'available'}，name 缺失仍落库

建议：在请求模型上为 name、photoUrls 增加必填约束（如 @NotBlank / @NotEmpty 或 OpenAPI required），校验失败统一返回 400 并给出字段级错误信息；同时补充契约测试覆盖缺失字段场景。

DEF-002 POST /pet 未校验 status 枚举取值，非法值 notastatus 被接受并持久化 high / contract

端点：POST /pet

证据：期望 400/422，实际 200，响应体 status='notastatus' 原样返回并保存

建议：将 status 定义为枚举（available/pending/sold）并在反序列化或业务层做白名单校验，非法值返回 400；数据库层可加 CHECK 约束兜底。

关联用例：API-011

DEF-003 GET /user/login 缺少 username/password 时未返回 400，反而创建了登录会话 high / contract

端点：GET /user/login

证据：期望 400，实际 200，响应体 'Logged in user session: 7180693170507649666'，空凭据即建立会话

建议：对 username/password 增加必填校验，缺失时返回 400；同时排查空凭据是否可绕过认证（存在安全隐患），建议改为 POST + 认证失败返回 401。

关联用例：API-019

DEF-004 GET /pet/1 查询已存在宠物返回 404，疑似测试数据未预置或被并发用例清理 medium / test_issue
